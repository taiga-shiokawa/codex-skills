# CLIで使う

このパッケージは、親Luna、モデル別の担当エージェント、振り分けスキルを組み合わせる。モデル選択はスキルを読むAIが判断するため、厳密なプログラム上の状態機械ではない。起動スクリプトは担当モデルの設定と親モデルを固定し、再試行の判断はスキルと記録に従う。

## Windows PowerShell

このスキルを `~/.codex/skills/dev-orchestrator` に配置する。通常のCodex CLIのインストール・ログインを済ませ、開発プロジェクトのフォルダで以下を実行する。`CODEX_HOME` を設定している場合は、その配下の `skills` を使う。

```powershell
& "$env:USERPROFILE\.codex\skills\dev-orchestrator\scripts\Start-OrchestratedCodex.ps1"
```

起動後は通常の日本語で作業を依頼する。開始時の依頼も渡せる。

```powershell
& "$env:USERPROFILE\.codex\skills\dev-orchestrator\scripts\Start-OrchestratedCodex.ps1" -Project 'C:\src\my-project' -Prompt '検索APIを実装して、必要なテストを実行して'
```

プロンプトは引数として渡され、シェルのコマンドとして評価しない。PowerShellで `$` やバッククォートを含む依頼を書く場合は、上の例のようにシングルクォートを使う。

スクリプトは初回に専用のエージェント定義4個を `$CODEX_HOME/agents`（未設定なら `~/.codex/agents`）へ配置する。同じ内容なら再利用し、同名で異なる内容があれば上書きせず場所を知らせる。通常の `config.toml`、既定モデル、承認・サンドボックス設定は書き換えない。

実行内容だけ確認する場合は `-DryRun`、担当エージェントの配置だけなら `-InstallOnly` を使う。`-DryRun` はファイルを作成せず、モデル呼び出しもしない。

配置済みなら、直接起動することもできる。

```powershell
codex -m gpt-5.6-luna -c 'model_reasoning_effort="medium"' '$dev-orchestrator を使って、以後の開発作業をモデル別に委任してください。'
```

## 既存セッション・デスクトップアプリ

新しいセッションで `$dev-orchestrator` を指定する。親モデルをLunaにしてから開始すると、この運用に合う。スキルの読み込みだけで既存の親モデルは切り替わらない。登録済みの役割、またはモデル指定に対応したサブエージェントツールがあれば委任できる。アプリで設定がまだ見えない場合は新しいセッションから使う。

CLIでは `/agent` で子の活動を確認できる。サブエージェントの実際のモデルは実行時の設定・活動情報で確認し、回答中の自己申告だけで判定しない。権限・ログイン・利用上限に起因する停止はエスカレーションの対象外。

## 運用の例

| 依頼・状態 | 動作 |
| --- | --- |
| 「この関数を説明して」 | 親Lunaで回答、必要ならLunaへ限定調査を委任 |
| 「READMEと設計書の重複を整理して」 | Solへ委任 |
| 「検索機能を追加して」 | Terraへ委任。設計判断が必要ならその部分をSolへ |
| Terraで同じ不具合への修正・検証が2回不成立 | 該当する問題だけSolへ |
| Solでも2回不成立 | 試行履歴と一次情報をAstraへ渡す |
| Astraが修正方針を特定 | Terraで実装・検証、必要ならSolで文書更新 |
| 利用上限に到達 | 記録を残し、別モデルへの自動再試行で回避しない |

## 確認した根拠

2026-09-07にローカルのCodex CLI 0.146.1で、モデル指定オプションと4モデルのカタログ掲載を確認。カタログ掲載は個別アカウントでの実呼び出し成功を保証しない。

同日に、隔離した小さなコード修正で親Lunaから子Terraへの委任を実機確認し、両セッションの実モデル設定を確認した。子が修正したコードのテストは、子の環境でPythonがPATHから見つからなかったため、検証側でPythonの絶対パスを指定して実行し成功した。Sol・Astraへの自動昇格は実モデルを呼び出す試験までは行っていない。ランチャーはドライラン、空白を含むパス、特殊文字を含む依頼の保持、初回・再配置、同名設定の保護を確認済み。

- [OpenAI公式：サブエージェント](https://learn.chatgpt.com/docs/agent-configuration/subagents) — CLIとアプリの委任、モデル指定、専用エージェント定義。
- [OpenAI公式：設定リファレンス](https://learn.chatgpt.com/docs/config-file/config-reference) — `agents` と推論量の設定。

利用回数の目安はスキルに固定しない。委任には親と子の両方の消費があるため、実測なしに節約率を保証しない。
