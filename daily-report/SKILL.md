# 開発日誌と管理台帳の更新

当日の作業内容を会話とローカルの根拠から整理し、Wordの開発日誌とExcelの管理台帳を安全に更新する。

- 既定の日報フォルダ: `C:\Users\GOOYAラウンダー6\gooya.co.jp\MySharePoint - DailyReport`
- Word: `yyyymmdd_開発日誌.docx`
- Wordテンプレート: `開発日誌_テンプレート.docx`
- Excel: `開発日誌_管理台帳.xlsx`、シート「日誌一覧」

ユーザーが別の日報フォルダを明示した場合は、その指定を優先する。

書き込み前に必ず [references/template-map.md](references/template-map.md) を全文読む。

## 鉄則

1. docx/xlsxの読み書きには同梱のNodeスクリプトだけを使う。PowerShellや.NETでZIPを展開・再圧縮しない。
2. 作業時間、時間帯、達成度、進捗率は常に空欄にする。ユーザー本人にしか分からない値を推測しない。
3. 1日1ファイル、台帳は1日1行にする。既存の日付分は更新し、重複を増やさない。
4. 既存内容を黙って消さない。空段落には `fill`、既存セクションへの追記には `append` を使う。
5. 書き込み前に対象ファイルを一時ディレクトリへバックアップし、書き込み後に必ず読み戻して検証する。
6. 一般のWord/Excel編集手段やOfficeアプリの直接操作へ切り替えない。同梱スクリプトが失敗したら原因を直す。

## 1. 実行環境と対象を確定する

次を確定する。

```text
skills_dir = このSKILL.mdがあるディレクトリ
folder     = ユーザー指定の日報フォルダ、未指定なら既定フォルダ
today      = 環境コンテキストの現在日付
docx       = folder\yyyymmdd_開発日誌.docx
xlsx       = folder\開発日誌_管理台帳.xlsx
template   = folder\開発日誌_テンプレート.docx
```

Node.jsは `Get-Command node` で解決する。見つからない場合はCodexのワークスペース依存関係を読み込み、返されたNode.js実行ファイルの絶対パスを使う。

作業用一時ディレクトリをシステムの一時領域に作る。例:

```powershell
$tempRoot = Join-Path ([IO.Path]::GetTempPath()) ("codex-daily-report-" + [guid]::NewGuid())
New-Item -ItemType Directory -Path $tempRoot | Out-Null
```

この一時ディレクトリにバックアップ、`ops.json`、`data.json` を置く。処理が完了しても、同じターン中はバックアップを削除しない。

## 2. 事前チェックを行う

- `folder`、テンプレート、台帳が存在することを確認する。欠けている場合は書き込みを始めず報告する。
- `folder` に `~$` で始まるWord/Excel一時ファイルがある場合、対象ファイルが開かれている可能性が高い。ユーザーに閉じてもらうよう依頼して停止する。
- 旧命名 `開発日誌_yyyymmdd.docx` だけが存在する場合は、正命名へリネームする。旧名と正名の両方がある場合は、勝手に統合・上書きせずユーザーへ確認する。
- 既存の対象docxとxlsxを `$tempRoot` にコピーしてバックアップする。新規docxの場合も、コピー元テンプレートとxlsxをバックアップする。
- 作業ディレクトリがGitリポジトリなら、当日の履歴を読み取り専用で確認して会話内容の裏取りに使う。Git履歴だけで作業内容を決めない。

## 3. 日報内容を組み立てる

主な材料は当日の会話と実際の変更・検証結果にする。事実と未完了事項を分ける。

- 本日の目標: 当日の作業目的を1〜2文でまとめる。
- 作業内容表: 最大6行。各行を「作業内容／分類／進捗・成果」に分け、成果は確認できた結果まで書く。時間帯は空欄にする。
- 実装・変更内容: 対象ファイル、変更点、必要な設計判断を簡潔に書く。
- 問題・エラー表: 実際に起きたものだけを「事象／原因／対応」で書く。無ければ空欄にする。
- 学び・気づき: 次回以降にも使える一般化した知見だけを書く。
- 明日の予定: 未完了タスクや次の検証を具体的に書く。
- 共有事項・依頼・懸念: ユーザー操作が必要なことや運用上の注意を書く。無ければ空欄にする。

プロジェクト名は会話、作業ディレクトリ、既存日報から特定する。既存の日報に正しい案件名がある場合は変更しない。

## 4. Wordを作成または更新する

### 新規作成

テンプレートを正命名へコピーし、書き込み前に段落を確認する。

```powershell
Copy-Item -LiteralPath $template -Destination $docx
& $nodeExe "$skillsDir\scripts\read-docx.js" $docx
```

[references/template-map.md](references/template-map.md) の段落マップを使い、`$tempRoot\ops.json` をUTF-8で作成する。形式は次の配列とする。

```json
[
  {"op":"fill","index":3,"lines":["2026/08/13（木）"]},
  {"op":"fill","index":7,"lines":["プロジェクト名"]}
]
```

適用する。

```powershell
& $nodeExe "$skillsDir\scripts\fill-docx.js" $docx "$tempRoot\ops.json"
```

### 既存ファイルの更新

既存ファイルでは段落インデックスがテンプレートから変わり得る。必ず `read-docx.js` で現在の全段落を確認し、固定ラベルを目印に書き込み先を決める。

- 空の段落・表セルへ書く場合は `fill` を使う。
- 既存セクションへ内容を足す場合は、セクション末尾の段落へ `append` を使う。
- 日付、記入者、案件名などの既存値が正しければ触れない。
- 別プロジェクトの内容が既にある場合も消さず、作業表の空行または該当本文へ追記する。

### Wordの検証

書き込み後に `read-docx.js` を再実行し、日付、案件、作業表、各本文セクションが意図した位置にあることを目視確認する。`fill-docx.js` の `ok: true` だけで完了判定しない。

## 5. Excel管理台帳へupsertする

`$tempRoot\data.json` をUTF-8で作成する。

```json
{
  "date": "YYYY-MM-DD",
  "project": "Wordの基本情報と同じ案件名",
  "summary": "主な作業内容の要約。1〜2文で簡潔に記す",
  "issues": "課題・懸念",
  "tomorrow": "翌日の予定",
  "link": "Wordファイルの絶対パス"
}
```

- 課題・懸念が無い場合、`issues` キーは省略する。
- 更新時、既存値を保持したい列のキーは省略する。
- 作業時間、達成度、進捗率に相当する値は含めない。

実行して読み戻す。

```powershell
& $nodeExe "$skillsDir\scripts\upsert-ledger.js" $xlsx "$tempRoot\data.json"
& $nodeExe "$skillsDir\scripts\read-ledger.js" $xlsx
```

次を確認する。

- `mode` が `update`、`insert`、`extend` のいずれかである。
- 対象日の日付行が1行だけである。
- B列とH列が数式のままである。
- E列の進捗率を変更していない。
- C、D、F、G、I列が意図した内容である。

## 6. 失敗時に復旧する

- スクリプトがエラーを返したら、PowerShellのZIP操作や別ライブラリで代替しない。対象ファイルのロック、JSON、段落インデックス、テンプレート構造を確認する。
- 書き込み後の読み戻しで破損や位置ずれが判明した場合、処理を継続せず一時ディレクトリのバックアップから対象ファイルを復元する。
- 復元した場合は、何を戻したかと再実行していないことをユーザーへ明示する。

## 7. 完了報告を行う

次を簡潔に報告する。

- 更新したWordファイルへの絶対パスリンク
- Wordに記入・追記したセクション
- Excel台帳の行番号と `mode`
- 読み戻し確認の結果
- 作業時間、時間帯、達成度、進捗率を空欄のまま残したこと
- バックアップを置いた一時ディレクトリ（復旧が必要な場合に使えるよう、そのターンでは残す）
