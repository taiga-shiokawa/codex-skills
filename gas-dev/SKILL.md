# GAS開発の一気通貫フロー

GAS開発を「取得 → 初期要求 → 永続文書 → 実装 → リモート反映」の順で進めるオーケストレーター。各フェーズの詳細を再実装せず、その時点で該当するCodexスキルの `SKILL.md` を完全に読み、承認条件と成果物を含めて従う。

| Phase | 内容 | 使用するスキル | 完了の目印 |
| --- | --- | --- | --- |
| 1 | GASをローカルへ取得 | `$gas-clone` | `.clasp.json` |
| 2 | アイデア・要求の起点を整理 | `$init-idea` | `docs/ideas/initial-requirements.md` |
| 3 | 永続的な開発文書を整備 | `$dev-docs init` | `AGENTS.md` と永続文書7点 |
| 4 | 変更を設計・実装・検証 | `$add-feature` | ステアリングと承認済み実装 |
| 5 | GASリモートへ反映 | `$gas-push` | push完了 |

ユーザーが指定したスクリプトIDまたはURLはPhase 1へ、開発したい内容はPhase 2の初期要求とPhase 4の変更要求へ引き継ぐ。

## 状態検出

最初に `scripts/state.ps1` をこのプロジェクトを作業ディレクトリとして実行する。返されたJSONの `suggestedPhase` は推奨開始点であり、ユーザーが完了済み工程や開始フェーズを明示した場合はその指示を優先する。

- `1-gas-clone`: `.clasp.json` がない。
- `2-init-idea`: 初期要求メモがない。
- `3-dev-docs-init`: `AGENTS.md` または永続文書7点が不足している。
- `4-add-feature-or-5-gas-push`: 開発前提は整っている。未実装の要求ならPhase 4、実装済み変更の反映だけならPhase 5へ進む。

開始時に「Phase Nから始める理由」を1行で共有する。状態検出だけでユーザーが明示した工程を勝手に省略しない。

## フェーズの進め方

1. 各フェーズ開始前に、該当するインストール済みスキルの `SKILL.md` を読み、その手順に従う。
2. フェーズ完了ごとに、成果物と次フェーズを簡潔に報告する。
3. 該当スキルがドラフト確認、アーキテクチャ選択、実装承認、push確認などで停止を要求した場合は必ず停止する。承認を推測しない。
4. ユーザーが一部フェーズだけを求めた場合は、必要な前提を確認したうえで指定範囲に限定する。
5. エラーや不足があっても、別フェーズの操作で迂回せず、そのフェーズの停止条件に従う。

## GAS固有の橋渡し

- **Git**: clasp clone直後はGitリポジトリでないことがある。履歴管理を希望する場合はPhase 2の前に `git init` と初回コミットを提案するが、強制しない。`.clasp.json` の共有方針はユーザーまたはプロジェクト規則に従う。
- **文書の受け渡し**: Phase 2の `docs/ideas/initial-requirements.md` はPhase 3の真の情報源になる。Phase 3以降は、ユーザー要求、`AGENTS.md`、現行の永続仕様という各スキルの優先順位に従う。
- **push対象**: `docs/`、`.steering/`、`AGENTS.md` は通常GASへpushされない。必ずPhase 5の `clasp status` で実際の対象を確認する。
- **検証**: Apps Scriptランタイム、DriveApp、SpreadsheetApp、トリガー、権限はローカルだけでは完全に再現できない。Phase 4では純粋ロジックのテスト、静的確認、レビューを行い、実ランタイム確認はpush後にApps Scriptエディタや対象スプレッドシートで行う。
- **実装から反映**: Phase 4の実装と検証が承認範囲内で完了したらPhase 5へ進む。pushの対象点検、上書き警告、承認条件は `$gas-push` を優先する。
- **デプロイ**: pushはソース反映であり公開版の更新ではない。デプロイはユーザーが別途依頼し、対応する手順が定義されている場合だけ扱う。

## 安全条件

- 全フェーズを1回の承認でまとめて許可されたものと扱わない。
- 各スキルの既存ファイル保護、認証、GitHub操作、push、force操作の承認条件を維持する。
- GASのGoogle認証を代行しない。
- ユーザーの未コミット変更、リモート変更、既存文書を勝手に破棄・上書きしない。
